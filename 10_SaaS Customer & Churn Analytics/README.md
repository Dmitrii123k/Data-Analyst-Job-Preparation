# SaaS Customer & Churn Analytics

## О проекте

Аналитический проект по исследованию SaaS-бизнеса с фокусом на клиентскую базу, подписки, выручку, churn, использование продукта и работу службы поддержки.

Цель проекта — определить основные характеристики клиентского оттока, оценить его финансовое влияние и сформировать практические рекомендации по удержанию клиентов.

Проект объединяет **SQL, Python и BI-визуализацию в Metabase**.

---

## Бизнес-задачи

В рамках проекта решались следующие задачи:

* анализ клиентской базы и подписок;
* анализ активных подписок и тарифов;
* расчёт MRR и ARR;
* анализ churn rate;
* анализ churn по тарифам, отраслям и странам;
* выявление основных зарегистрированных причин churn;
* анализ upgrade и downgrade перед churn;
* анализ реактиваций клиентов;
* оценка финансового влияния churn;
* анализ использования функций продукта;
* анализ ошибок продукта;
* анализ обращений в поддержку;
* оценка satisfaction и escalations;
* статистическая проверка потенциальных факторов churn;
* формирование бизнес-рекомендаций.

Для проверки потенциальных факторов churn использовались:

# Statistical Analysis

| Фактор  | Тест           | P-value | Результат                       |
| ------- | -------------- | ------: | ------------------------------- |
| Тариф   | Chi-square     |  0.9993 | Значимой связи нет              |
| Отрасль | Chi-square     |  0.0657 | Значимой связи нет при α = 0.05 |
| Страна  | Chi-square     |  0.6588 | Значимой связи нет              |
| Seats   | Mann–Whitney U |  0.6919 | Значимого различия нет          |
| MRR     | Mann–Whitney U |  0.6317 | Значимого различия нет          |

Ни один из проверенных факторов не продемонстрировал статистически значимой связи с churn при `α = 0.05`.

При этом отсутствие статистической значимости не означает отсутствие бизнес-различий.

# Business Insights

### 1. Churn является существенной бизнес-проблемой

Churn rate составляет **22%**.

### 2. Тариф не является очевидным рычагом удержания

Churn практически одинаков для всех тарифов.

### 3. Product experience требует дополнительного анализа

`Features` — наиболее распространённая зарегистрированная причина churn events (**19%**).

Необходимо исследовать product usage и ошибки непосредственно перед churn.

### 4. DevTools требует дополнительного исследования

Наблюдаемый churn составляет **30.97%** против **22%** в целом.

Статистическая значимость не подтверждена, поэтому это направление для исследования, а не доказанный фактор churn.

### 5. Есть потенциал для win-back

Reactivation rate составляет **10.17%**.

### 6. Финансовая ценность churn-клиентов существенна

Текущие подписки клиентов с churn events связаны примерно с **$2.36 млн MRR**.

Поэтому retention следует приоритизировать не только по вероятности churn, но и по финансовой ценности клиента.

# Recommendations

## 1. Product Churn Analysis

Исследовать:

* снижение использования функций перед churn;
* error rate;
* отсутствие активности;
* использование ключевых функций.

## 2. DevTools Analysis

Провести дополнительную сегментацию DevTools по:

* MRR;
* seats;
* product usage;
* support tickets;
* churn reasons.

## 3. Win-back Strategy

Изучить характеристики реактивированных клиентов:

* причина churn;
* время до реактивации;
* тариф после возвращения;
* MRR до и после возвращения.

## 4. Early Warning System

Для будущей модели churn использовать:

* снижение product usage;
* рост ошибок;
* обращения в поддержку;
* satisfaction;
* downgrade;
* inactivity;
* изменение MRR.

## 5. Financial Prioritization

Для retention-кампаний использовать комбинацию:

**Churn probability × MRR**

Это позволит приоритизировать клиентов с наиболее высоким потенциальным финансовым риском.

# Итог

Проект показал, что churn является значимой бизнес-проблемой: **22% клиентов имеют churn**.

При этом стандартные клиентские характеристики — тариф, страна, размер клиента и MRR — не показали статистически значимой связи с churn.

Таким образом, высокий churn не объясняется одним очевидным клиентским фактором.

Наиболее перспективные направления для дальнейшего анализа:

* product usage;
* product errors;
* DevTools;
* support interactions;
* поведение клиентов перед churn;
* reactivation;
* predictive churn analysis.

Следующий логичный этап — перейти от ретроспективного анализа уже произошедшего churn к **предиктивному выявлению клиентов с высоким риском оттока** и приоритизации retention-мер по потенциальному финансовому эффекту.
